✅ Prerequisites
HIGH
Microsoft Graph API — Mail.Send permission
Most companies will not grant this. Tenant admin consent required.
Why it blocks
Sending email programmatically via Graph API requires an Azure AD app registration with Mail.Send scope. This needs tenant admin consent — a step most IT departments refuse for third-party desktop apps. Even with consent, conditional access policies, DLP rules, and MFA requirements can silently block it.
Mitigation
Primary fix: Use mailto: links only. The system composes the email and opens the user's default mail client pre-filled. User clicks Send. No API. No admin consent. Works everywhere Outlook is installed (which is every Sesame machine).
Fallback: Asana email-to-task (see Comms Options tab). No Graph API needed at all.
HIGH
mailto: link has no default mail client
Machines where Outlook isn't installed or registered as default email app.
Why it blocks
If no mail client is set as default, clicking a mailto: link either does nothing or opens a "how do you want to open this?" dialog that confuses non-technical employees. Web-only email users (Gmail in browser) will hit this. Field engineers may have company phones but no desktop email client configured.
Mitigation
Detection: The prereq checker tests whether a mailto: handler is registered. If not, it flags it and guides the employee to set Outlook as default before install.
Alternative flow: If no mail client, wizard offers "Copy completion summary to clipboard" so employee can paste it into a web email manually — crude but reliable.
MED
Completion email silently not sent
mailto: opens but employee closes without sending. Champion never knows they're done.
Why it blocks
The wizard can't confirm the email was actually sent — it only opens the mail client. An employee who closes Outlook without sending leaves the champion with a gap in their rollout tracking.
Mitigation
Primary: Write completion record to a shared OneDrive JSON file (completions.json in the employee pack folder) — no email required for tracking. Email becomes a nice-to-have notification, not the source of truth.
Champion dashboard: Reads completions.json rather than inbox. Reliable, no mail dependency.
MED
Asana API requires Business/Enterprise tier
As you identified — API key access for automation is gated behind paid tiers.
Why it blocks
Full Asana API automation (creating tasks, reading projects programmatically) requires a Business or Enterprise subscription. The API key itself is available on free/basic, but rate limits and features needed for proper automation hit a paywall.
Mitigation
Free tier workaround: Every Asana project has a unique email address. Employees cc that address on their completion email and Asana creates a task automatically — no API key, no subscription upgrade. Champion sets up the project once, shares the email address, it goes into company-profile.json.
LOW
OneDrive sharing link requires sign-in
Some SharePoint/OneDrive tenants disable "anyone with link" sharing.
Why it blocks
If the tenant has disabled anonymous sharing (common in some M365 configurations), the download link in the onboarding email will demand a login. Employees who haven't signed into M365 on their machine get a login wall before they can download anything.
Mitigation
Champion setup wizard asks: "Does your OneDrive allow anonymous sharing?" If no, the email template switches to "People in your organisation" link type. All Sesame employees have M365 accounts so this is a minor friction, not a blocker.
HIGH
DeepSeek API blocked by corporate firewall
DeepSeek is a Chinese-origin service. Many UK/EU corporate firewalls block Chinese domains by policy.
Why it blocks
Corporate firewalls — particularly in finance, legal, or regulated industries — often use geo-blocking or domain reputation lists that flag deepseek.com. Even if not actively blocked, some DLP policies alert on API traffic to non-approved services.
Mitigation
Prereq check tests connectivity to deepseek.com, anthropic.com, openai.com before install. If DeepSeek fails, wizard defaults to Anthropic or OpenAI.
OpenRouter as proxy: DeepSeek models are available via OpenRouter (openrouter.ai) which is a US-domiciled aggregator — less likely to be blocked. Single OpenRouter key covers all providers.
MED
Outbound HTTPS inspection / SSL interception
Some corporate proxies do SSL termination — breaks API certificate validation.
Why it blocks
If the corporate network uses a proxy that intercepts HTTPS (common in larger companies for DLP), the API calls see a corporate certificate, not the provider's cert. This causes certificate validation errors that look like network failures to the user.
Mitigation
Prereq check: Detects proxy environment (HTTP_PROXY env var, Windows proxy settings). If found, warns the employee to inform IT that the app makes API calls to approved LLM endpoints.
Electron NODE_TLS_REJECT_UNAUTHORIZED: Configurable in enterprise mode — but only set this as a last resort with IT sign-off.
MED
API key validation fails on first use — user gives up
Error messages from LLM providers are cryptic. Employees who entered the wrong key think the app is broken.
Why it blocks
A typo in an API key, a key without billing attached, a free-tier key without credits, or a key for the wrong model all return different error codes. If the wizard just says "invalid key" the employee has no idea what went wrong.
Mitigation
llm-validator.ts must distinguish: 401 (wrong key) vs 402/429 (no credits/quota) vs network error vs timeout. Show a specific human message for each: "Key looks wrong — check for extra spaces", "Key is valid but has no credits — top up at X", "Can't reach the service — may be blocked on your network."
LOW
LLM API key shared across employees = one billing account
If the champion provides a company key, all usage runs against one account. No per-employee spend visibility.
Why it blocks
A single shared API key means no usage attribution, no ability to set per-user spending limits, and a single point of failure if the key leaks or the account runs out of credits mid-month.
Mitigation
Decision point: Company key (simple, champion manages billing) vs employee-own keys (each employee registers and pays or claims). For a company Sesame's size, one company key per provider with monthly billing is simpler. DeepSeek allows sub-key creation for usage tracking.
HIGH
Windows SmartScreen blocks unsigned installer
"Windows protected your PC" — most employees will stop here.
Why it blocks
Any .exe not signed with an Extended Validation (EV) code signing certificate triggers SmartScreen. The warning is aggressive — it says "Windows protected your PC" with no obvious safe path. Non-technical employees will not know to click "More info → Run anyway." This will be the single biggest employee-facing blocker.
Mitigation
Buy an EV code signing certificate. ~£300–600/year from DigiCert, Sectigo, or GlobalSign. EV certs build SmartScreen reputation immediately. Worth doing before any rollout.
Stop-gap: The quick-start PDF includes a screenshot of exactly what to click. Buys time while cert is obtained.
HIGH
No local administrator rights
Many employees on managed Windows machines cannot install software.
Why it blocks
Managed Windows endpoints (common in any company with proper IT) restrict software installation to admins. The installer will either fail silently or prompt for credentials the employee doesn't have. Field engineers especially are likely on tightly managed machines.
Mitigation
Per-user install mode: electron-builder can build a per-user NSIS installer (no admin required) that installs to %APPDATA% instead of Program Files. Add perMachine: false to electron-builder.yml.
MSI for IT push: For machines that need IT-managed install, build an MSI that IT deploys via Intune — no employee action needed.
MED
macOS Gatekeeper blocks unsigned DMG
Same problem as SmartScreen but on Mac. Requires Apple notarisation.
Why it blocks
macOS will refuse to open a DMG that isn't signed with an Apple Developer certificate and notarised through Apple's servers. The error message "can't be opened because Apple cannot check it for malicious software" is shown with no obvious workaround.
Mitigation
Apple Developer account: £79/year. electron-builder has built-in notarisation support. Required for any Mac deployment beyond the pilot. The quick-start PDF covers the right-click → Open workaround for the pilot phase only.
MED
Corporate antivirus flags Electron app
CrowdStrike, Defender for Endpoint, or Symantec may quarantine the app.
Why it blocks
Electron apps bundle Node.js and Chromium — patterns that some heuristic AV engines flag as suspicious, especially unsigned ones. CrowdStrike in particular is aggressive about new unsigned binaries making network connections.
Mitigation
Code signing solves most of this. For the pilot: submit the binary hash to your AV vendor's whitelist portal before distribution. Champion should test on a machine with the company AV before sending to employees.
LOW
Keytar fails on Windows with no Credential Manager
Rare but possible on stripped-down or kiosk-mode Windows builds.
Why it blocks
keytar uses Windows Credential Manager to store API keys. On some domain-hardened machines the credential manager service is disabled by GPO. The app crashes on first key storage attempt with a native module error.
Mitigation
AES-256 fallback: CoWork-OS already has this. If keytar throws, fall back to encrypted electron-store. Less secure but functional. Log the fallback in the completion record so IT knows.

Ranked by reliability and ease of setup. Recommendation at the bottom.

📁Option A — OneDrive shared completions.json RECOMMENDED
Wizard writes a completion record to completions.json in the shared OneDrive folder. Champion reads this file to track who is done. No email, no API, no auth. Uses file permissions Sesame already has. Works 100% of the time if OneDrive is accessible (which it is — it's where they downloaded the installer from).

Completions.json entry: { "employee": "Alice", "role": "engineering", "timestamp": "2026-06-12", "providers": ["deepseek"], "integrations": ["outlook", "sharepoint"], "machineHash": "abc123" }
📧Option B — mailto: + Asana project email (free tier) GOOD FALLBACK
Wizard opens mailto: pre-filled with the champion's email AND cc'd to the Asana project email address (e.g. x+projectcode@mail.asana.com). User clicks Send. Email arrives in champion inbox AND creates an Asana task automatically. No API key. No subscription upgrade. Subject line contains [SESAME-AI] for inbox filtering.

Setup: Champion creates one Asana project called "Sesame AI Rollout", copies the project's unique email address, pastes it into champion-setup.js when asked. That's it.
💬Option C — Microsoft Teams incoming webhook IF TEAMS IS USED
If Sesame uses Teams, an incoming webhook posts a card to a channel with no OAuth, no Graph API, and no admin consent required. The webhook URL is generated in the Teams channel settings by any channel owner — takes 2 minutes. App POSTs to the webhook URL on completion.

Limitation: No email thread. Just a notification. Good for real-time visibility, not for formal tracking.
🚫Option D — Microsoft Graph API Mail.Send AVOID
Requires Azure AD app registration, tenant admin consent, OAuth token refresh flow, and ongoing maintenance. Even if granted, can break if the tenant admin revokes consent or changes conditional access policies. The failure mode is silent — app thinks it sent, admin didn't receive. Not worth the complexity when Options A and B are simpler and more reliable.
▶ Recommended combination
Primary tracking: completions.json in OneDrive (Option A) — always reliable, no dependencies.
Notification: mailto: + Asana project email (Option B) — human confirmation, Asana task created for free.
Prereq failures: mailto: only — no Asana needed, just champion email.
This combination has zero infrastructure dependencies beyond OneDrive, which is already in use.
