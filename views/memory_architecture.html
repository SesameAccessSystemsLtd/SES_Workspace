What it holds
Topic frequency map. "5 people worked on shaft specifications this week." No names. No content. No queries.
Who can see it
Champion sees aggregate counts. Employees see "others are working on similar topics" nudge only.
Tech
Lightweight JSON index synced to OneDrive. Tags only. Auto-generated by local agent, reviewed before upload.

Layer 3 — ✋ Opt-in Contributed Knowledge — shared insights employees choose to publish
What it holds
Summaries, how-tos, project learnings, supplier notes — published deliberately by the employee.
Who can see it
All employees. Champion can approve before publishing. Author is attributed.
Tech
Shared SharePoint folder or OneDrive library. Champion-managed. Versioned documents.
↑ champion curates and formalises into official process ↓
Layer 4 — 👑 Champion-managed Process Library — official knowledge pushed to all instances
What it holds
Approved procedures, compliance requirements, standard templates, best practices. Versioned with dates.
Who can see it
All employees read it. Champion writes and updates it. Pushed via [SESAME-AI] email or config sync.
Tech
quick-wins.json + role-pack-map.json + a company knowledge base file. Baked into Employee Package updates.

The goal: surface "Alice and Bob are solving the same problem" without either of them knowing their queries are being read.

🏷️Mechanism: Topic Tags, not Query Content
Each agent silently tags its tasks with topic labels — never the actual words typed. Tags are things like shaft-spec, listed-building-compliance, client-onboarding. These tags sync to the shared Pattern Index (Layer 2). Content never leaves the device.
💡Collaboration Nudge (employee-facing)
When 2+ employees share a topic tag, their local agent surfaces a gentle nudge: "3 colleagues are also working on listed-building compliance this week. There may be shared knowledge worth checking." No names. Just the signal. Employee decides whether to ask the champion to connect them.
📊Champion Dashboard (aggregate view)
Champion sees: which topic clusters are active, which teams are working on similar things, where duplication is happening. Example: "Engineering and Installation are both researching the same supplier specification — should these teams talk?" Champion chooses whether to act.
🔗Cross-Department Signal
If Sales is researching a building type that Engineering is simultaneously specifying a lift for — the Pattern Index will show overlapping tags. Champion can surface this: "Sales opportunity and Engineering spec may relate to the same client." This is the silo-breaker, without exposing individual work.
⚠️ Important: the Pattern Index never stores employee names alongside tags. It stores counts and department labels only. "Engineering × 3, Sales × 1" — not "Alice, Bob, Charlie from Engineering."

Three mechanisms keep knowledge from going stale.

📅Freshness Dating
Every item in Layers 3 and 4 is tagged with a creation date and a review-by date (set by champion or author). The local agent checks these dates. Items past review-by surface as: "This process document is 6 months old and may not reflect current practice." Champion gets a weekly digest of items due for review.
⚡Contradiction Flagging
When an employee's local agent generates a finding that conflicts with an item in the Process Library (Layer 4), it flags it: "Your research suggests X, but the company standard says Y. Flag this to your champion?" One click sends a [SESAME-AI] Knowledge Conflict email to the champion, who can update the process library or dismiss it.
🔄Champion Push Updates
When the champion updates quick-wins.json, role-pack-map.json, or the Process Library, these propagate to employees on next launch (or via a [SESAME-AI] Update Available email). The employee's instance pulls the new config from the OneDrive folder. No reinstall required — just a config refresh.
🧠CoWork-OS Dreaming (already built)
CoWork-OS has a built-in background process called Dreaming that curates local memory overnight — merging duplicates, compressing old context, and surfacing forgotten insights. This works on Layer 1 automatically. In Stage 3, a shared version can run across the contributed knowledge base to consolidate organisational learning.
🏗️ Build order: Freshness dating and champion push updates in Stage 1. Contradiction flagging in Stage 2. Shared Dreaming in Stage 3. Don't build what you don't need yet.
